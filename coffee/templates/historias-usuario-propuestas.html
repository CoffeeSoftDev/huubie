Vista de historias de usuario para CoffeePlanner

Hoy el agente entrega una tabla markdown de 8 columnas donde una sola celda —criterios de aceptación— trae 20 líneas de especificación. En un chat de 420 px eso es ilegible. La propuesta es que CoffeePlanner deje de escribir la tabla en prosa y emita un bloque de datos que el visor pinta con una plantilla fija, igual que ya hace con Mermaid, Chart.js o los diagramas draw.io.

↑ scroll horizontal infinito, criterios en una sola línea

Qué falla exactamente

  • 8 columnas en 420 px

    El CSS del chat pone white-space: nowrap por celda: la tabla se vuelve una tira horizontal.

  • El criterio es el 80% del valor y es lo que peor se ve

    Los <br> del markdown se aplastan en un párrafo continuo; se pierden filterBar / tabla / modal.

  • Sin jerarquía visual

    Perfil, sprint, fechas y reglas ** IMPORTANTE ** pesan lo mismo que el resto.

  • No hay salida

    Para llegar al Excel del equipo hay que copiar a mano y reacomodar cada celda.

  • El formato depende del modelo

    Cada corrida escribe la tabla un poco distinta; nada garantiza las 8 columnas.

2Propuesta — tres vistas de un mismo dato

Un único bloque de datos, tres formas de pintarlo. Las tres viven en la misma tarjeta y se cambian con los botones del encabezado.

Cada historia es una ficha plegable. Cerrada se lee como backlog; abierta muestra los criterios reagrupados en filterBar / tabla / modal / reglas, con color por tipo. Entra completa en el ancho del chat.

Visualizar los documentos de un proyecto en un árbol de carpetas, pudiendo buscar por nombre de proyecto y por nombre de documento.

El apartado debe contener los siguientes elementos:
filterBar
  • Buscador de proyecto ( placeholder "Buscar proyecto…" )

  • Botón de nueva carpeta
  • Botón de subir archivo ( primary )

  • Nombre de carpeta con contador de documentos
  • Al seleccionar una carpeta se listan sus documentos

  • Nombre del documento
  • Extensión ( badge )
  • Tamaño
  • Última modificación
  • Botones de acción
    • ver, renombrar, eliminar

Decisiones de diseño

  • El apartado es el título

    Es la columna con la que el equipo busca la historia después; va en MAYÚSCULAS como en el Excel.

  • El perfil, como chip

    La columna "Yo ( Usuario)" se lee de un golpe sin robar ancho a la funcionalidad.

  • Criterios plegados y por bloque

    filterBar azul, tabla verde, modal terracota, cards violeta. Se recupera la jerarquía que el markdown aplana.

  • Las reglas se destacan

    * en ámbar, ** IMPORTANTE ** en rojo: es donde vive el riesgo del desarrollo.

  • Una fila por perfil sigue siendo una ficha

    Si la pantalla la usan GERENTE y CONTABILIDAD, salen dos fichas con el mismo apartado y distinto chip.

Las tres acciones del encabezado —copiar tabla markdown, exportar a Excel y abrir en pestaña completa— son las mismas que ya tienen las tarjetas de Mermaid y draw.io en ia-render.js. No hay componente nuevo que mantener.

La tabla del Excel, columna por columna. Los criterios viven colapsados en su celda (3 bloques · 2 reglas) y se despliegan en una fila propia, a todo el ancho. Es la vista para revisar con el cliente y la que se copia al Excel.

3Cómo se logra: el agente emite datos, no maquetación

CoffeePlanner escribe un bloque ```stories. El visor lo pinta. Si el bloque no llega, el markdown de siempre sigue funcionando.

```stories
proyecto: Admin de documentos
historias:
  - usuario:  ADMIN
    apartado: EXPLORADOR DE PROYECTOS
    quiero:   Visualizar los documentos…
    beneficio: Para localizar rápido…
    criterios:
      intro: El apartado debe contener…
      bloques:
        - tipo: filterBar
          items:
            - Buscador de proyecto
            - Botón de subir archivo ( primary )
        - tipo: tabla
          titulo: Listado de documentos
          items:
            - Nombre del documento
            - Extensión ( badge )
            - item: Botones de acción
              sub: [ ver, renombrar, eliminar ]
      reglas:
        - nivel: nota
          texto: Solo rutas dentro de la raíz…
        - nivel: importante
          texto: Guardar sobreescribe el archivo…
```
Tipos de bloque cerrados: filterBar · cards · tabla · modal · tabs · nota. Salen del vocabulario obligatorio de historias-de-usuario.md, así que el agente no inventa nombres nuevos.

Qué se tocó · implementado

  1. La regla del agente

    Sección §8 en historias-de-usuario.md con el esquema del bloque y el vocabulario cerrado de tipo, más el punto 9 del checklist. Recargada con load-coffee-planner.php --force.

  2. El renderer

    renderStories() en ia-render.js, junto a renderMermaid / renderChart, con parser propio de YAML (subconjunto) y de JSON. Si el bloque no cumple, se queda como código: nunca rompe el mensaje.

  3. El CSS

    Clases .ia-stories-* en visor.css sobre las variables --vsr-*: dark y claro sin trabajo extra. Las reglas de tablas markdown de chat.css / visor.css se acotaron con :not(.ia-xls) para que no se cuelen.

  4. Las salidas

    Copiar la tabla markdown de 5 columnas, exportar .xlsx con SheetJS (CSV si no está cargado) y expandir a pantalla completa.

  5. Dónde funciona

    Chat con Agentes, drawer CoffeeIA y Lab — las tres páginas que cargan ia-render.js. Se implementó una sola vez.

Estado: implementado.
